# 模型提示词与路由参考

本文件是按需读取的经验参考，不是 Asynx API 契约，也不是供应商的固定 Prompt 语法。

使用前先读取当前模型目录：

```bash
python3 "<skill-dir>/scripts/asynx.py" models
```

模型、能力、价格和可用性会随部署变化。用户明确指定模型时，优先尊重用户选择；没有指定模型时，使用 Skill 的固定默认模型；只有用户明确要求推荐时，才使用下面的路由建议。

## 使用原则

### 简单请求直接提交

“生成一张红色椅子”“把刚才改成蓝色”这类请求不需要 Prompt 优化，也不需要为了选模型额外查询模型目录。保留用户原话，使用默认模型和参数。

### 复杂请求再结构化

当请求涉及复杂编辑、多参考图、海报、信息图、文字排版或组图时，可以按以下顺序整理意图：

1. 主体和动作；
2. 场景和空间关系；
3. 构图、视角和画幅；
4. 材质、光线和色彩；
5. 文字内容和排版；
6. 必须保留、允许修改和禁止出现的内容。

不要把互相冲突的风格、构图和比例要求堆在一起。优先保留用户明确提出的约束，删除不会改变结果的装饰词。

### 编辑任务优先写清“保留”和“修改”

编辑 Prompt 建议明确区分：

```text
保留：主体、姿态、透视、光线或背景中不应改变的内容。
修改：需要替换、添加、删除或重绘的内容。
范围：修改发生在哪个对象或区域。
```

这比只写“改得更高级”“优化一下”更容易得到稳定结果。使用 Mask 时，Prompt 仍然要说明修改目标；Mask 是编辑引导，不等于像素级锁定。

## 模型经验

| 模型 | 适合场景 | Prompt 组织倾向 |
| --- | --- | --- |
| `gpt-image-2.5-sunburst` | 编辑精度、多轮修改、复杂产品和品牌视觉 | 详细写修改区域、保留内容和视觉约束，避免模糊的全局改写 |
| `gpt-image-2.5-flare` | 当前模型目录可用时的快速日常生图 | 采用主体、场景、风格、构图四段式，保持 Prompt 简洁 |
| `gemini-3.1-flash-image` | 多参考图、快速创意、多轮编辑、对象和人物一致性 | 给参考图编号并说明每张图的职责；写清哪些元素保持一致、哪些元素变化 |
| `gemini-3-pro-image` | 复杂海报、信息图、图文布局、产品 Mockup | 明确画布比例、区域布局、文字层级和每个区域的内容 |
| `doubao-seedream-5-0-260128` | 中文风格化创作、多图融合和组图 | 用中文描述主体、动作、服饰、材质、场景、光线和风格；多图时标明“图 1 / 图 2”的作用 |

### GPT Image

GPT Image 官方示例使用自然语言，不要求固定的关键词格式。经验上，编辑任务最重要的是描述不应改变的内容：

```text
保留原图中的键盘布局、透视关系和桌面位置。
只将键盘外壳改为深绿色阳极氧化铝。
保持原有光线、背景和镜头角度不变。
```

Sunburst 更适合需要精确编辑的任务。Flare 可用于追求速度的普通生图，但仅在当前模型目录可用且用户明确选择时使用。

### Gemini Image

Gemini 适合把多张参考图当作上下文来描述。可以使用这种结构：

```text
参考图 1：人物姿态。
参考图 2：服装设计。
参考图 3：背景色调。

将这些元素组合成一张完整海报。
保持人物脸部特征和服装结构一致，只改变背景和光线。
```

Gemini 的语义局部编辑用自然语言描述“只修改某个对象”，不要把它当成 OpenAI 风格的独立 Mask 文件流程。复杂图文布局优先选择 Pro；快速多轮编辑优先选择 Gemini 3.1 Flash。

### Seedream

Seedream 的公开示例和实际使用经验都更适合详细的中文场景描述。多图时不要只把图片列表交给模型，要说明每张图的角色：

```text
图 1：人物姿态和脸部特征。
图 2：服装和材质。
图 3：背景和色彩氛围。

保持人物和服装一致，将三张图融合成一张商业海报。
```

组图请求还要区分“跨图保持一致的元素”和“每张图主动变化的元素”。例如角色外观、服装和画风保持一致，只改变时间、地点或动作。

目前没有稳定、权威且专门针对 `doubao-seedream-5-0-260128` 的完整 Prompt 语法规范，因此不要把第三方教程中的关键词顺序、权重写法或所谓“万能负面词”当成硬规则。

## 常见任务路由

| 需求 | 优先考虑 | 额外提示 |
| --- | --- | --- |
| 普通快速生图 | 默认模型；用户明确追求速度时可考虑 Gemini 3.1 Flash | 不要为了普通请求增加复杂 Prompt |
| 精确换色、换背景 | GPT Image、Sunburst | 明确保留内容和修改范围 |
| Mask 局部重绘 | 支持 Mask 的 GPT Image | 同时写清编辑目标和禁止改变的内容 |
| 多张参考图融合 | Gemini 3.1 Flash、Seedream | 给每张参考图分配角色 |
| 复杂海报和信息图 | Gemini 3 Pro、GPT Image | 描述画布分区、文字层级和版式 |
| 中文风格化创作 | Seedream | 详细描述主体、材质、光线和风格 |
| 多轮连续修改 | Gemini 3 系列、GPT Image 对话式接口 | 后续修改只描述本轮变化，避免重复整个需求 |

## 不要做的事

- 不要默认给每个 Prompt 添加长串负面词；多数模型没有统一的负面 Prompt 契约。
- 不要把摄影术语、艺术家姓名、风格词和技术参数无限叠加。
- 不要在用户未要求时偷偷改变主体、风格、构图或文字内容。
- 不要把模型经验当成能力声明；参考图数量、Mask、尺寸和输出数量以当前模型目录及上游结果为准。
- 不要为了模型推荐给每个普通请求增加一次网络模型目录请求。
