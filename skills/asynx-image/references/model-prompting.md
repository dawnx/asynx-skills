# 模型与提示词

仅在用户要求模型推荐、Prompt 优化，或需梳理多图关系、复杂图文布局时使用；明确的换色、换背景和角色修改不需要先读本文件。本文件提供组织意图的建议，不是模型能力契约，也不要求先查询模型目录。

## 选择模型

没有指定模型时沿用脚本默认值；用户明确选择时尊重其选择。需要推荐、消除名称歧义或确认 Mask 等特殊能力时，才查询当前目录：

```bash
python3 "<skill-dir>/scripts/asynx.py" models
```

根据返回的可用性、编辑能力、输入数量、尺寸和价格筛选。不要只凭型号名称断言某个版本更快、画质更好或编辑更精确；目录未提供的效果差异应说明为待验证的经验。实际请求还受本客户端的[输入限制](operations.md#输入图片)约束。

## 组织复杂需求

用户已经写好的 Prompt 默认保留；需要协助组织时，写清主体、空间关系、画幅、光线材质、文字内容及不能改变的部分。不要求固定关键词顺序，不机械添加负面词或摄影术语。

| 场景 | 应写清的内容 |
| --- | --- |
| 换色、换背景、局部修改 | 修改对象和范围，以及需要保留的主体、视角、布局 |
| 多参考图融合 | 每张图的角色，例如姿态、服装、背景；避免相互冲突的要求 |
| 海报、信息图、产品展示 | 画布方向、分区、文字原文、层级和留白 |
| 组图 | 跨图保持一致的元素，以及每张图允许变化的内容 |

### GPT Image 编辑

自然语言描述修改范围即可，不需要套用固定标签格式。例如：

```text
保留原图中的键盘布局、透视关系和桌面位置。
只将键盘外壳改为深绿色，保持原有光线和背景。
```

需要 Mask 时先确认所选模型支持；Mask 是编辑引导，不保证未选区域像素完全不变。

### Gemini Image 多参考图

让文字中的编号对应实际输入顺序，例如：

```text
参考图 1 提供人物姿态，参考图 2 提供服装，参考图 3 提供背景色调。
将这些元素组合成一张竖版海报，保持人物脸部特征和服装结构一致。
```

语义编辑可以描述“只修改背景”等要求，不因为模型能编辑图片就推断它支持独立 Mask 参数。

## 连续修改

当前 Skill 每次编辑都是新的图片任务，不会自动传递完整对话历史。使用用户选定的上一轮图片，并写清本轮修改和仍需保留的约束；必要信息不能只依赖“照之前说的做”。
