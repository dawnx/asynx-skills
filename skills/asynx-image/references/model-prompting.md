# 模型与提示词

仅在用户要求探索或推荐模型、优化提示词，或需梳理多图关系、复杂图文排版时阅读。普通生成和明确修改直接按主文调用。

## 选择模型

未指定模型时沿用脚本默认值；用户明确指定时以其选择为准。仅在需要推荐、确认模型可用性或消除名称歧义时查询当前目录：

```bash
python3 "<skill-dir>/scripts/asynx.py" models
```

目录提供可用模型、生成/编辑用途与价格，不提供尺寸、输入数量或蒙版等参数能力说明。不得仅凭型号名称断言某版本更快、画质更好或编辑更精确；参数支持情况按服务说明和已确认的使用结果判断。实际请求还受本客户端[输入限制](operations.md#输入图片)约束。

## 组织复杂需求

用户已写好的提示词默认保留；需要协助组织时，应写清主体、空间关系、画幅、光线材质、文字内容及不可改变的部分。不要求固定关键词顺序，也不机械堆叠负面词或摄影术语。

| 场景 | 应写清的内容 |
| --- | --- |
| 换色、换背景、局部修改 | 修改对象与范围，以及需保留的主体、视角、布局 |
| 多参考图融合 | 每张图的角色，例如姿态、服装、背景；避免相互冲突的要求 |
| 海报、信息图、产品展示 | 画布方向、分区、文字原文、层级与留白 |
| 组图 | 跨图需保持一致的元素，以及每张图允许变化的内容 |

### 图片编辑与局部修改

用自然语言描述修改范围，无需套用固定标签格式。例如：

```text
保留原图中的键盘布局、透视关系和桌面位置。
只将键盘外壳改为深绿色，保持原有光线和背景。
```

使用蒙版前须先确认所选模型支持；蒙版为编辑引导，不保证未选区域像素完全不变。

### 多参考图创作

文字中的编号须对应实际输入顺序，例如：

```text
参考图 1 提供人物姿态，参考图 2 提供服装，参考图 3 提供背景色调。
将这些元素组合成一张竖版海报，保持人物脸部特征和服装结构一致。
```

语义编辑可直接描述“只修改背景”等要求，但不得因模型可编辑图片而推断其支持独立的蒙版参数。

## 连续修改

使用用户选定的上一轮图片，并写清本轮修改内容与仍需保留的约束；关键信息不得仅依赖“照之前说的做”。
